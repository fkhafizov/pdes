📚 RAG Parameter Guide

📥 Ingestion & Chunking

Chunk Size Critical

Number of tokens per text chunk. Sweet spot ≈ 256–768. Too small → fragments lose context. Too large → dilutes relevance signal. Smaller chunks generally = higher precision but lower recall.

Chunk Overlap

% of overlap between consecutive chunks. Prevents key sentences from being cut at boundaries. 10–20% overlap is typical. Beyond 30% gives diminishing returns and increases storage cost.

Splitter Strategy Impact High

How documents are split: Character (naive) → Token → Recursive (LangChain default) → Sentence → Semantic (preserves meaning best). Semantic splitting significantly improves context quality.

🔢 Embedding

Embedding Dimension

Dimensionality of the vector space. Higher dim = richer representation but slower ANN search. 768 (BERT-base) is the standard sweet spot; 1536–3072 for high-precision tasks.

Embedding Model Impact High

Domain-specific fine-tuned models outperform general models significantly. OpenAI text-embedding-3-large leads benchmarks; BGE and Cohere are strong open-source alternatives.

🗂️ Indexing

Similarity Metric

Cosine (angle between unit vectors) is best for normalized embeddings. Dot product is fastest. L2 works for raw unnormalized embeddings. For most embedding models: use cosine.

Hybrid Search Impact High

Blend of dense (semantic) + sparse (BM25 keyword) retrieval via Reciprocal Rank Fusion. A weight of 0.3–0.5 toward BM25 often beats either method alone, especially for named entity queries.

🔍 Retrieval

Top-K Precision↔Recall

Number of chunks passed to the LLM. Higher K = better recall but more noise. K=3–5 for high precision tasks; K=8–15 for recall-critical tasks. Pair with re-ranking if K is large.

Re-ranking Precision +15–20%

Cross-encoder model re-scores the top-K retrieved chunks for relevance. Dramatically improves precision at the cost of +200–500ms latency. Use BGE-Reranker or Cohere Rerank.

Query Rewriting

LLM rephrases the query before embedding to improve retrieval. Particularly useful for conversational, ambiguous, or poorly phrased questions. Adds ~200ms and one LLM call.

Contextual Compression

Extracts only the relevant sentences from each retrieved chunk before passing to LLM. Reduces noise and saves context window space. Adds ~100ms overhead.

🤖 LLM & Generation

LLM Quality Cost ↑↑

The single biggest lever for faithfulness. GPT-4o / Claude 3.5 Sonnet cost ~50× more than GPT-3.5 but dramatically reduce hallucination. Even good retrieval fails with a weak LLM.

Temperature

Set near 0 (0.0–0.2) for RAG QA tasks. Higher temperature encourages the LLM to generate beyond retrieved context → increases hallucination and hurts faithfulness.

Context Window

Limits how many chunks fit in the prompt. Larger windows (128K+) enable higher Top-K. However, LLMs suffer "lost-in-the-middle" degradation on very long contexts.

📊 RAGAS Framework: Context Precision (fraction of retrieved chunks that are actually relevant), Context Recall (fraction of relevant chunks that were retrieved), Faithfulness (answer grounded in context?), Answer Relevancy (answer addresses the question?).
